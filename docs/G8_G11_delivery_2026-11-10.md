# G8.3–G11 交付 / REAL_ONLY（2026-11-10）

> **两种不同结论，不得混淆：** 源码级工程改造已完成并做有限测试；完整历史 PIT 个股、真实预测优势、严格历史回测及连续真实前向模拟仍未验收。严禁生成假行情、假模型概率、假 P&L、事后伪造订单或放开最终封存测试。

## G8.3｜公司行为多页来源审计

- 新模块 `data/action_pages.py` 只读取 `data/raw/receipts` 与 `data/raw/objects` 中实际保存的 Alpaca 原文，不联网填缺页、不自动写任何 PIT/资格/交易表。
- CLI `action-pages --symbols AAPL --start 2024-01-01 --end 2024-12-31 --page-size 1000`；页面 `/data` 可录入完全相同的已归档请求参数。
- 逐页核对请求哈希、原文字节哈希、`next_page_token`、单次分页时间先后、跨页事件 ID 去重；最新首次请求存在未完成链时，不自动回退到旧成功链。
- **范围限制**：完成某个查询的分页，不等于发行人所有历史事件、退市、公布时间、公司行为权益结算或历史投资组合成分均已证明。状态始终为 `source_query_pagination_complete`，`historical_pit_eligible=false`、`historical_backtest_eligible=false`。

## G9｜市场 × 风格 × Alpha × 风险研究

- 新模块 `research/four_layers.py` 使用冻结的 G6 多因子策略及其哈希验证的 `features.parquet`、`labels.parquet`，再次要求同一来源快照 SHA256 与真实 Yahoo 价格源一致。
- 指定验证期使用历史落后或当日收盘时可计算的代理：SPY 过去20会话收益、IWD 相对 IWF 过去20会话表现、SPY 20日波动率与此前126日波动率的60%分位数阈值。不能对未来数据做前向填充。结果按 5 套预先固定条件展示验证期 IC、有效天数、样本占比、块自举95%区间。
- 用途仅为 `RETROSPECTIVE_FOUR_LAYER_ABLATION_ONLY`。不同条件对应**不同日期子样本**，因此 IC 差异不能被解读为交易盈利增量，尚无概率校准、交易成本与可执行模型；绝不输出假候选。
- 进入 `/strategies` 选择已冻结、同一真实源的多因子策略，点击“四层模型增量研究”；CLI：`four-layer-research --strategy-version UUID`。

## G10｜严格历史回测阅读器与状态纠错

- 原 `backtest/metrics.py` 无论来源都返回 `SYNTHETIC_NOT_READY`，与证据通过的真实原价执行路径不一致。现在仅在现有 `simulate()` 必须先通过 `DatasetBundle.require('historical_backtest')` 的条件下报告 `MODELED_HISTORICAL_FILLS_NOT_BROKER_ORDERS`。
- 严格 P5 接纳后，manifest 删除过时的合成/幸存者偏差标记，改存对应验证范围的真实证据资格。共用报告生成器只在该严格状态、`research_grade=true` 且 `historical_decision_eligible=true` 时改变提示；其他所有报告仍标记 NOT_READY。
- 新模块 `backtest/verified_results.py` **只读**扫描真实 `outputs/system/<run_id>` 的 P5 产物，核验 manifest 的模式、来源、时间/模型摘要及文件 SHA256。`/backtests` 才展示实际存在的情景、净值曲线、交易和成本。
- CLI：`backtest-results` 查看列表；`backtest-results --run-id UUID --scenario h3_cost_10bps` 查看真实完成结果。浏览器 `GET /api/v1/backtests/verified`。
- **没有**新增真实券商下单、伪造执行或不受审核的前向订单。回测启动沿用现有严格 CLI `backtest`，必须事先提供 PIT 验证的冻结模型档案、原始开盘数据和完整公司行为证据。

## G11｜运行检查及缺口

- `tests/test_g8_g10_contracts.py` 检查没有来源时必须拒绝、日期不能来自未来、分页缺失与哈希篡改会 BLOCK、不同查询不能混、未验收回测无指标可展示。测试中的空公司行为 JSON **只做协议单元测试**，不得写入生产数据/报告或当作真实外部证据。
- `scripts/check_ui_smoke.py` 为可选 Playwright 无数据拒绝态检查，不调用真实网络、不注入行情或 P&L，仅检查九页面初始化与新操作入口。需要安装 Playwright 与 Chromium；它**不能代替**实际启动的服务、数据库与源数据端到端验收。
- 此环境没有 DuckDB、PyArrow 与本机数据档案，故未运行全仓库数据库集成、真实源正向链路、G9 真实 IC 或真实 P5/前向账户，测试和浏览器结果不能宣称全部完成。
- 既有 GitHub Actions 按用户要求只支持手动触发；不应擅自开启自动工作流。

## 实际验收仍须外部条件

1. **历史 PIT 证券主库**：稳定证券/发行人 ID、历史上市退市/更名、有效日及已公布时点；将股票、ETF、ADR 依法区分，避免当前目录回填历史。
2. **公司行为完整性**：供应商分页在明确查询时点通过核验只是第一步；还需历史有效的全资产覆盖、跨来源对账、公告时间、分红支付/碎股/退市结算。
3. **四层模型**：来自独立 PIT 数据的真实个股训练，样本外校准、模型冻结、事前设定成本/阈值、负面对照和统计稳健性，严禁反复使用封存测试调参。
4. **历史回测**：历史股票池和逐会话价格可用时点、逐事件结算、模型档案 SHA256、回测 P5 产生真实核验报告；没通过继续 BLOCKED。
5. **前向模拟**：采集连续真实收盘快照，T 时点冻结信号，T+1 模拟成交并标记成本，跨日账本现金/持仓/缺失交易日对账，绝不事后填入历史订单。
6. **环境验收**：在用户本机安装依赖，用真实仓库完整运行 `uv run --locked pytest -q`、真实 API、浏览器和定时任务、备份恢复；记录失败、跳过与具体准入证据。
