# 美股多层量化研究系统——Web UI / UX 交互规范与使用手册 REAL_ONLY v2.1

> 配套文档：`../02_技术与研究/核心研究开发规范_REAL_ONLY.md`（研究和计算规范仍以主文档为准）  
> 使用对象：个人量化研究者（非高频交易员）；平台：桌面浏览器优先，最低有效宽度 1280 px，适配 1024 px；移动端只读概览可后置。  
> 产品属性：研究、策略评估、每日信号、模拟交易。**禁止真实资金下单；禁止任何合成、演示、随机行情/预测/收益进入 Web 产品。无数据时显示 NOT_READY 与可操作修复说明。**

## A. 设计目标与信息架构

### 核心目标
1. 让非程序员在 UI 完成因子创建、单因子分析、多因子组合、回测和查看每日信号，无需日常运行 CLI。
2. 明确区分 `研究假设`、`探索性结果`、`独立样本外检验`、`模拟交易` 四种证据等级，不把历史结果包装成未来预测。
3. 所有数值可追溯到 `run_id`、时间戳、数据源、模型版本、配置、股票池与收益标签定义。
4. 与 Python 研究核心解耦：界面只调用后端服务和异步任务，严禁在前端重新实现财务计算/回测算法。

### 一级导航（侧栏）
1. `研究总览` `/overview`：市场状态、风格变化、实验结果、数据健康、今日关注事项。
2. `市场分析` `/market`：SPY 市场方向概率、下行风险、市场广度、波动和信用代理。
3. `风格监控` `/styles`：SMB/HML/MOM/RMW/CMA 等历史因子；可获得的 ETF 代理；风格轮动与转折。
4. `因子实验室` `/factors`：因子库、参数版本、表达式/模板、新实验、IC、分组、衰减、稳定性。
5. `策略工作台` `/strategies`：因子组合与过滤、模型版本、退出规则、风险预算、冻结策略配置。
6. `回测中心` `/backtests`：实验设置、运行、可视化结果、成本敏感性、消融实验、逐笔成交。
7. `每日信号` `/signals`：当日候选股票、预测分布、策略依据、风险审查、模拟委托草稿。
8. `模拟组合` `/paper`：持仓、现金、模拟委托、成交、净值、复盘、收益归因。
9. `数据与设置` `/data`：数据源状态、更新时间、覆盖率、quality flags、凭证配置指南、策略参数。

### 全局固定区域
- 左侧栏：九个一级菜单 + `帮助/指南`。
- 顶部栏：数据 as-of 交易日选择器；数据健康（正常/降级/阻断）；运行模式（`OBSERVATION`/`EXPLORATORY`/`RESEARCH_GRADE`/`FORWARD_PAPER`，按证据准入）；正在使用的策略与模型版本；“最近更新于”时区标识（ET）。
- 全局操作：`刷新已到达数据`、`查看运行记录`；异步任务显示进度、阶段和失败原因；不得用假加载动画代表已完成的计算。
- 全局风险约束：只要股票池存在幸存者偏差、历史数据不完整或预测未校准，所有相关视图显著显示研究限制，不可折叠成微小脚注。

## B. 各页面内容、交互及验收

### 1. 研究总览
**布局：** 顶部 `数据日期 / 运行状态 / 研究资格`；第二屏前展示市场摘要、风格雷达/横向强度条、Alpha 信号概况、持仓风险；底部近期实验与数据告警。  
**核心交互：** 点击任何指标下钻到详情页；日期切换后全页数据同步刷新；点击告警进入数据质量详情；一键打开“上次有效报告”。  
**验收：** 不混用不同 as-of 的板块；空数据时为引导态，不能显示零值伪装预测结果。

### 2. 市场分析
**布局：** 市场状态说明、`未来1/3/5日`切换、概率卡片（上涨/下跌尾部）、SPY 与市场广度时间序列、波动率与信用代理、模型校准图。  
**核心交互：** 改变预测窗口、查询某历史交易日的模型输出、查看每个特征的可用时间；叠加历史状态，不把事后标签用于当日视图。  
**验收：** `P(up)` 仅在模型已校准时显示为可用预测，否则展示“未校准/仅供研究”；历史日回看不能使用后续数据。

### 3. 风格监控
**布局：** 风格热力图、小盘/价值/动量/质量/低波动相对收益，4 态分类；经典因子 vs ETF 代理切换；因子收益累计曲线与转折观察。  
**交互：** 多选因子比较；5/20/60 日窗口；点选风格查看代表性构成、定义、数据发布延迟和阈值；`加入策略特征` 不直接下单。  
**验收：** French 因子与 ETF 代理均标明真实定义，French 当日因子若尚未发布则禁止作为当日决策输入。

### 4. 因子实验室（核心交互）
**三栏布局：** 左：因子列表（类别、状态、版本、最近 IC）；中：定义器（内置模板或白名单表达式、参数窗口、方向、缺失策略）；右：实验设置与预览。下方 Tab 为 `因子预览 / IC&显著性 / 五分组收益 / 衰减 / 行业与规模暴露 / 数据覆盖率 / 研究记录`。

**创建流程：**
1. 点击 `新建因子` → 选“反转/动量/波动率/流动性/规模/质量/自定义（安全表达式）”模板。
2. 设置名称（唯一）、经济假设、数据列、计算窗口、方向；显示“可用日期/样本覆盖率”预检查。
3. 点击 `验证公式`，在经过数据来源与时间戳校验的真实历史样本上展示前 10 行中间计算与缺失项；如不可用则阻断；任何除零、非法窗口报错。
4. 设置样本股票池、年份、预测窗口 H∈{1,3,5}、基准、行业中性化（可选）。
5. `运行初筛` 创建**不可变 experiment_id**；任务进入队列，结果显示真实进度。
6. 打开 IC、分组、稳定性分析；可 `复制为新版本`，不覆盖旧实验；比较新旧实验。
7. 仅在满足审计、数据完整性与样本外条件时允许标记 `已通过研究验证`，否则显示 `仅探索` / `数据不足`。

**关键安全限制：** 自定义表达式采用后端白名单 DSL/受限 AST，不允许任意 `eval`、文件访问、网络操作和 Python 代码执行。所有新因子输入必须重新检查 PIT；因子名称与配置存储版本不可变。

### 5. 策略工作台
**布局：** 左侧可选因子池；主区域显示策略构建器 `股票池 → 市场条件 → 风格条件 → Alpha 模型 → 信号过滤 → 风险约束 → 退出规则`；右侧运行资格清单。  
**交互：** 添加/移除因子、设置权重或选择预测模型、查看因子相关性；配置最大总仓位、个股/行业上限、ADV、止损；`保存草稿`→`校验`→`冻结策略版本`→`送去回测`。  
**验收：** 风格与市场因子不能直接与 Alpha 百分位评分相加而无清晰定义；冻结版本不可被直接修改，需复制新版本；未校验版本无法生成纸面建议。

### 6. 回测中心（核心交互）
**布局：** 左侧回测设置；结果区 Tab：`概览 / 净值与回撤 / 年度表现 / 交易与成交 / 分层对比 A–E / 参数敏感性 / 研究限制`。  
**交互流程：**
1. 选择冻结的 strategy_version 和历史 as-of 范围。
2. 系统自动显示训练/验证/测试分割、purge/embargo、股票池质量、交易 T+1 open、持有期及分边成本（bps）。
3. 启动前确认数据质量和 `研究级/探索性` 标识；若缺少 PIT 关键数据，不准宣称严格回测。
4. `运行回测` 异步任务，可取消；完成后保存 run_id、配置哈希和结果文件。
5. 图表与交易表联动：刷选日期范围 → 统计卡片同步更新；点击回撤区间 → 查看对应持仓与成交。
6. `与基线比较`、`比较两个策略版本`、`导出报告（HTML/CSV/JSON）`。
7. 最终封存测试集必须有显式一次性解锁流程和审计记录；不可在日常调参时反复泄漏测试集。

**验收：** 页面首屏同时展示净收益、最大回撤、交易成本、样本外资格状态；收益图不允许缺失成本口径；展示每侧/双边成本和成交模拟假设。

### 7. 每日信号（核心交互）
**布局：** 日期、策略版本、数据资格；候选股票表（Ticker、行业、1/3/5 日期望净收益、上涨概率、下行分位、流动性、阻断原因、拟分配权重）。  
**交互：** 筛选/排序/搜索；点击行打开右侧详情抽屉：`特征贡献（仅模型实际支持时显示）/ 市场与风格条件 / 风险限制 / 建仓与退出规则 / 版本溯源`；点 `加入观察` 或 `生成模拟委托草稿`，**绝不真实下单**。  
**验收：** 不生成/显示虚构概率。新鲜度不合格、缺失关键数据、策略未冻结时阻断“生成模拟委托”，同时说明原因。空列表属于有效的“当日无符合条件标的”状态。

### 8. 模拟组合
**布局：** 组合净值、现金、风险敞口、持仓表、委托列表、成交日志、收益归因。  
**交互：** 从每日信号建立模拟委托草稿 → 审核日期/股数/价格规则/成本 → `确认模拟委托`；按预定交易日录入模拟成交；允许撤销未成交草稿，但不直接编辑已记账成交，应使用审计调整记录。  
**验收：** 所有模拟交易明确 `PAPER ONLY`；不存在真实券商连接、付款或实盘按钮；任何模拟成交有日志与可复现的成交规则。

### 9. 数据与设置
**布局：** 数据源状态、最近完整日、覆盖率、历史缺口、Corporate Actions、泄漏检测、运行历史、凭证管理说明。  
**交互：** `检测连接`、`增量更新`、`审计数据`、`查看异常行`、`导出审计报告`；用系统凭证/本地 .env 配置，不在 UI 明文展示密钥。  
**验收：** 数据拉取失败保持旧的最近有效 as-of，明确提醒；绝不显示“更新成功”但实际没有获取新数据。

## C. 完整用户操作路径（用户手册）

### 新用户首次使用（仅真实数据）
1. 打开应用后首先进入 `数据与设置`，检查 API 配置、连接状态、覆盖范围与最近数据到达时间。
2. 若未配置数据源，显示 `NOT_READY · 尚无真实数据`；允许浏览页面说明与创建不执行的因子配置，但不显示任何行情、收益、历史交易或概率。
3. 配置凭证时只引导用户在本地安全环境变量中完成，不通过前端提交或记录明文密钥。
4. 点击 `检测只读数据权限`，必须真实访问受支持提供商；显示真实请求是否通过、feed、raw 口径、日期及已缓存快照。
5. 执行数据审计。符合要求的真实数据解锁相应研究能力；个股历史股票池不足时继续阻断严格回测。
6. 在因子实验室使用真实数据创建 `5日反转`，完成公式验证、样本覆盖检查后再运行初筛；没有合格数据就不运行。
7. 打开回测中心查看实际输出及其证据等级；只有满足完整数据能力门槛才允许严格回测。前向 paper 从真实开始日期积累，不能倒填。

### 日常收盘后使用（目标 3–5 分钟）
1. 进入 `研究总览`，确认交易日、数据截止时间、完整性与最近更新成功状态。
2. 查看市场的上行/下行风险与风格变化；只阅读模型实际支持的预测。
3. 打开 `每日信号`，筛掉缺失、低流动性及风险阻断候选。
4. 查看候选详情、计划仓位、净收益和退出规则；可选择创建模拟委托草稿。
5. 次日查看 `模拟组合` 的持仓与执行记录；定期到 `回测中心` 检查模型退化。

### 每周研究（目标 30–60 分钟）
1. 因子实验室：新建一个经济假设而非无目的参数搜索。
2. 运行初筛 → 比较 IC/分组/衰减/时间稳定性 → 排除无价值因子。
3. 策略工作台：复制旧策略成新版本，加入候选因子。
4. 回测中心：固定数据与成本设置做 A–E 消融，比较是否产生样本外增量。
5. 结果有价值时冻结策略版本；没有价值则记录为负面研究结论。

## D. 交互状态、提示与错误处理

| 状态 | UI 必须做什么 | 禁止做什么 |
|---|---|---|
| 空白首次使用 | 提示配置真实数据源；展示 NOT_READY 与缺失能力 | 展示任何虚构指标、收益或股票 |
| REAL_ONLY | 只在具备真实来源、时点和完整性证据时展示结果 | 任何 DEMO/Fixture/Mock 市场数据进入产品 |
| EXPLORATORY | 明示股票池/财务缺口，允许学习性研究 | 贴 `已验证` 标签 |
| 数据延迟 | 显示最后完整 as-of；阻断受影响的新信号 | 用昨天数据冒充今天 |
| 模型未校准 | 显示原始模型分数及风险说明，概率区标不可用 | 将 raw score 写成真实概率 |
| 计算进行中 | 显示可取消任务和排队/运行状态 | 假装立即完成 |
| 计算失败 | 保留错误日志和上次有效结果，提供重试 | 清空历史、静默 fallback |
| 回测未通过 | 展示负面统计和不通过原因 | 自动调参直到获得好看的收益 |
| 无股票信号 | 展示“当日无符合规则的股票” | 填充虚假候选 |
| PAPER | 只记录模拟委托成交，不触达实盘 | 出现真实下单能力 |

## E. 图表与设计规范
- 推荐布局：1440 px 桌面基准，侧边栏 220–240 px、主内容最大 1600 px、24 px 栅格；工作区密度中等。
- 信息层级：顶部决策状态 > 异常风险 > 主要图表 > 可钻取明细；不要把“需要帮助”放在同等视觉权重。
- 视觉：专业轻量深色工作台（或可切换浅色），中性色为主；绿/红仅用于有方向含义的涨跌/风险，**不能仅靠颜色传递状态**。
- 核心组件：状态标签、指标卡、走势图、因子排名条、可排序表、侧抽屉、分步创建器、日期选择器、成本滑杆、对比视图、数据质量面板、任务进度、来源说明。
- 数值规范：概率显示小数与样本外校准信息；百分比和 bps 严格区分；收益表标记毛/净口径；图表时间统一 ET，显示观测时点/信号日/成交日。
- 可访问性：键盘操作可达、对比度、焦点状态、表格可访问名称、空/加载/失败状态；响应式时不隐藏风险警告。
- 原则上同一页面至多一个主 CTA；次级动作使用次要按钮或文本操作。

## F. API 与前后端契约（建议）

**建议完整 Web 版架构：** React + TypeScript + Vite、Tailwind CSS + shadcn/ui、ECharts 或 Recharts；Python FastAPI 提供读取/提交任务接口；研究引擎仍为主文档中的 Python 包。禁止演示 Fixture；离线只能读取有来源与 SHA256 的真实历史快照。也可先用 Streamlit 验证功能，但正式 UI 不能只交付多个脚本按钮。

最少需要提供版本化 REST 契约（可按实际实现调整，保证功能等价）：

- `GET /api/v1/system/status`：模式、as-of、数据健康、任务状态。
- `GET /api/v1/market?asof=&horizon=`：市场预测/状态/可用性。
- `GET /api/v1/styles?asof=&window=`：风格收益和转折。
- `GET /api/v1/factors`、`POST /api/v1/factors`、`POST /api/v1/factors/validate`：因子管理、校验。
- `POST /api/v1/experiments`、`GET /api/v1/experiments/{id}`：异步研究任务与结果。
- `GET /api/v1/strategies`、`POST /api/v1/strategies`、`POST /api/v1/strategies/{id}/freeze`：策略版本。
- `POST /api/v1/backtests`、`GET /api/v1/backtests/{id}`、`GET /api/v1/backtests/{id}/trades`：回测运行、结果、成交。
- `GET /api/v1/signals?asof=&strategy_version=`：候选股和阻断原因。
- `POST /api/v1/paper/drafts`、`POST /api/v1/paper/drafts/{id}/confirm`：仅模拟委托。
- `GET /api/v1/data/quality`、`POST /api/v1/data/audit`：审计和质量状态。

通用响应需包含 `run_id`、`data_cutoff_utc`、`asof_date_et`、`data_quality_flags`、`model_version` 和 `source_provenance`；异步任务返回 `job_id/status/progress/error`；列表分页，任务支持幂等键。

## G. UI 开发计划、工期及验收

### P0–P6 联动开发（不另做孤立 UI）
- **P0（4–8 小时并行）**：建立产品导航、路由、主题、设计 Tokens、REAL_ONLY 守卫；全局来源、能力状态栏与真实空态。
- **P1（4–6 小时）**：数据与设置页面、数据源状态及审计结果展示。
- **P2（8–12 小时）**：因子实验室 MVP，模板选择、参数编辑、运行与报告页。
- **P3（5–8 小时）**：市场分析、风格监控、研究总览页面。
- **P4（5–8 小时）**：策略工作台、每日信号、详情抽屉及观察列表。
- **P5（6–10 小时）**：回测中心，研究资格、结果对比、成本和交易明细。
- **P6（5–8 小时）**：模拟组合、操作指南、端到端测试与易用性修正。

UI 额外投入约 **37–60 小时**；与原研究任务书估算的 72–120 小时合计约 **109–180 人工小时**。按每周 10–15 小时粗估约 **8–18 周**；若界面只做 5 页面精简 MVP，可进一步压缩。时间不是 Codex 的单次运行时长，也不包含购买/补齐研究级历史数据、实盘可用性的验证周期。

### UI 必须通过的端到端验收（至少）
1. 没有 API Key 且没有已审计真实快照时：全部数据视图显示 NOT_READY，因子实验、回测、模拟组合执行被明确阻断；不会有演示数据回退。
2. 日期 T 的特征不能泄漏 T+1 数据，用户尝试切到尚未完整的交易日会得到阻断说明。
3. 新建因子→参数验证→新实验→报告→复制为 v2→版本对比，全流程成功、可追溯。
4. 回测设置中修改成本，回测结果必须实际重算；不可前端只改显示数字。
5. 数据源失败时保留最后有效结果并标注过期，不输出新的交易候选。
6. 没有可用因子、没有信号、模型未校准、样本外为负，均有对应准确 UI 状态。
7. 所有 `确认模拟委托` 动作只写入本地 paper ledger，不调用实盘下单 API。
8. 使用 Playwright 测试桌面 Chrome，至少验证导航、实验任务、结果导出、模拟委托和异常状态。

## H. Codex 开发要求（以统一启动文件为准）

完整实现九个页面，但把 UI 能力解锁条件严格绑定后端的 `dataset_capabilities` 和证据状态；不允许前端自行计算或补造市场数据。所有真实结果必须展示源、as-of、数据截止、版本、覆盖、质量与限制。任何按钮仅在真实依赖全部满足时可用；不可用时明确阻断原因和修复路径。使用真实后端运行结果完成 Playwright 验收，没有合格数据则验证阻断逻辑，不能伪造通关。
