# 美股量化研究系统：真实数据唯一模式与全链路整改任务书

版本：2.0｜编制日期：2026-11-07｜用途：直接交给 Codex 在**现有项目仓库**执行。

> 最高优先级需求：系统生产、研究、前端、报告、回测和前向交易记录**只允许有来源可追溯的真实数据**。缺失数据返回 `NOT_READY / BLOCKED / N/A`；绝不以随机、模拟、合成、演示数据充数。策略回测允许使用真实历史行情和**明确标为“模型模拟成交”**的保守执行模型，严禁把模型成交表述为真实成交事实。

## 0. 不可妥协的设计决策

1. **REAL_ONLY** 是系统级不可被普通用户配置绕过的策略。生产、前端、API、批处理、日报、模型注册和模拟组合全部默认拒绝非真实数据。
2. 禁止在可运行产品中调用 `random/faker/synthetic/demo/mock/fixture/sample_prediction` 等生成行情、因子收益、模型效果、回测收益或持仓；不得把旧系统的示例盈利保留在页面初始状态。历史图表为空就显示“未达到真实数据验收条件”。
3. 测试中也不生成虚构市场记录。单元纯数学测试可使用简单标量验证公式；数据集成和回归测试使用经过来源核验的**真实历史事件/行情快照**（授权允许的情况下放在受控测试目录，附来源/时间/hash，严禁进入正式数据库）；CI 无法获得授权历史数据时相应测试列为 blocked，不能假装通过。
4. 接口错误、超时、数据不完整、时点不明、缺少可交易价格、公司行为未处理的证券：按影响范围停用该行/日期/策略，而不是自动替换为其他数据源后不留痕；若使用真实备源，须保存来源及口径差异。
5. 区分五种结果：**真实市场观察、历史探索性统计、严格历史回测、真实行情前向影子决策、券商真实模拟盘成交**。不允许互相冒名。
6. 严禁启用真实资金下单；未来如需交易须单独安全审计与明确授权。

## 1. 供应商方案（采购之前先测权限，不允许臆测可用）

### 方案 A：零付费、真实数据先运行
- **Alpaca 历史 SIP**：优先日线 `feed=sip`、`adjustment=raw`、明确 `start/end`、`timeframe=1Day`、处理每一页 `next_page_token`。无实时 SIP 权限时查询截止必须晚于数据至少 15 分钟；IEX 实时成交量不可冒充全市场。检查最近完整交易日、拆股、停牌、日期、预/盘后合并口径、分页、上限、覆盖率。账户是否能访问必须真正调用 API。
- **SEC EDGAR 原始申报**：通过 submissions / filing 原文件 / accession / `acceptanceDateTime`、XBRL 提取历史财报；历史 FSDS 是可辅助重建的 as-filed 数据，不代表该汇编包当年就存在。首次可用时间使用可核验的原始披露时间+安全时滞；不允许事后重编指标回填到公告前。
- **Fama-French 历史因子**：用于历史风格分析、比较研究；对每日真正可交易的信号，须核验其发布时间，不能直接把某日最终发布的收益视为当日收盘可用。必要时自行从已合格股票池构造风格组合。
- **局限**：如果缺少有效历史退市证券名册、稳定证券身份与最终退市处理，就不能以“美股全市场严格历史回测”交付；可在明确涵盖范围内做真实行情观察/有限样本探索与从当前起的前向记录。此时不要伪造历史股票池。

### 方案 B：以最低可控成本补齐历史个股研究（推荐作为采购评估目标，非已购买）
- **Sharadar 10 Years Prices**：公开标价 USD 19/月（199/年）；包括股票/基金、行为及身份参考表，但不含 PIT 财报主体数据。
- **Sharadar 10 Years Bundle**：公开标价 USD 49/月（399/年）；包含 `stocks`, `funds`, `tickers`, `actions`, `fundamentals`, `daily`, `sp500` 等。研究区间 2017–2026 先核验实际滚动 10 年起点、每日更新时刻、退市证券覆盖、PIT 财报缺失与限制条款。
- `stocks.open/high/low/close/volume` 默认已拆股调整；使用官方 `closeunadj` 转换方法还原 raw O/H/L/V。重建值必须与独立真实历史样本核验精度，不可直接叫“原始市场实际成交”。正式**执行**优先采用 Alpaca `raw` 日线；Sharadar 可作为历史股票池与特征的主要来源。
- `fundamentals` 的 ARQ/ARY/ART 是 as-reported 时间维度；MRQ/MRY/MRT 属于最新值，不用于历史 PIT 特征。对只有日级披露时间的记录，使用下一完整交易时段生效的保守原则。
- **买之前**验证免费样本是否确实可调用以及列字段/时长/权利；不能把小样本当全市场。

### 方案 C：替代付费路线
- **Norgate Platinum**：USD 346.50/6个月或 630/年（公开价），提供更多退市证券和历史指数成分，适合量价和股票池；历史行业变更/PIT 财务仍需另源补齐。验证当前平台（尤其 Windows/Python 集成）和许可；不要购买 Gold 期待有退市及历史成分。
- **CRSP**：已有学校/机构许可时评估 PERMNO + 退市回报；不是默认免费选项。
- **Massive**：官方有历史 reference tickers、按日有效股票名单，但 Basic 历史参考资料只允许最近 2 年；历史有效状态不是完整的“当日已知版本”，也没有跨一切公司行为绝对稳定的永久 ID。不要作为 2017 起免费完整股票池的保证。

### 采购放行门槛
`provider_proof.json` 必须记录 `plan_verified`, `earliest_verified_day`, `latest_verified_day`, `active_count`, `delisted_count`, `bars_count`, `missing_count`, `sample_split_verified`, `sample_symbol_reuse_verified`, `pricing_verified_at`, `licensing_notes`。以上字段不可凭文档宣传直接标绿：必须有 API/下载运行日志。

## 2. 统一数据合同与真实来源证据

### 核心约束
- 一切记录有 `source_id`, `source_endpoint`, `retrieved_at_utc`, `source_record_id`(若有), `raw_response_sha256`, `data_version`, `ingestion_run_id`。
- 一切可作为信号的记录必须有 `event_time_utc`, `published_at_utc`(可核验时), `available_at_utc`, `decision_time_utc`；不确定时间时 `available_at_utc = NULL`，拒绝进入相关信号，不能设置为行情收盘时间进行“修复”。
- 按 **America/New_York** 交易所日历处理早收盘、DST、停牌；数据库 UTC 存储，同时保留 exchange session date。
- `source_version_kind`：`contemporaneous_snapshot` / `documented_original_filing` / `retrospective_effective_dated` / `current_revised_snapshot`，并明确后两种不能自动当历史当日可见。
- 对于每日真实行情、已知当前可用行情，在信号生成前保存快照并冻结哈希；禁止后续 API 改写使既往信号无声改变。回溯重算必须新建 run_id。

### 最小表结构
```

security_master(security_id,provider_id,issuer_id,share_class,first_traded,last_traded,status,metadata_provenance)
```

## 3. 15 项卡点的独立工程修复方案与验收

### B01 历史行情/API 账户权限
- 实现 `provider_probe` 命令：实际验证 2017/2020/2024/最近完整交易日各期，20 个基准 ETF + 分层真实股票样本及已退市样本（有许可时），两种以上行情日、早收盘、拆股前后；分页取全并核对总数。
- 对 HTTP 401/403/422/429/5xx、空结果、分页中断分别定义失败码。缓存原始请求参数和响应 hash，支持断点续传。
- **通过**：日志证明每项权限/日期/完整页数，而不是“接口页面存在”。

### B02 Raw 与调整价格的严格隔离
- `prices_daily` 只记录真实 raw OHLCV；`feature_prices` 使用单独 split-adjusted、total-return-adjusted 视图；所有字段强制携带口径与提供者。
- 执行撮合只读真实 raw 和公司行为账本。若从 Sharadar 重建原始 OHLCV，标记 `reconstructed_raw` 并用 Alpaca 或交易所历史记录交叉验证，失败不用于成交。
- **通过**：AAPL 2020 拆股、GE 2021 反拆股（如所选供应商提供）前后价格与成交量检查；原始/复权不串列。

### B03 历史股票池、退市与有效范围
- 建立按 `session_date` 生效的历史可投资名册；来源必须支持历史挂牌、退市状态及股票类型；不允许以今天 still-active list 回填。
- 退市无法核验的证券不得假设收盘以 0 或最新价成交，持仓与收益应 `BLOCKED_UNRESOLVED_DELIST`；并输出受影响组合数量。
- **通过**：至少各 1 个已退市、换代码、IPO、常规存活案例的真实来源可追溯；未来才有的股票不在过去名单中。

### B04 稳定身份、代码复用、复合证券
- 自建不可变 `security_id`，ticker 仅作为有效期别名；引入提供商 permaticker 或有授权的 PERMNO / FIGI，并把 CIK 作为 issuer 辅助而非股类 ID。
- 添加换名、复用、A/B 股、并购、分拆映射的来源证据，冲突时 BLOCKED。
- **通过**：同一 ticker 两个历史主体无法错误拼接时间序列。

### B05 公司行为与事件账本
- 同时保存公告、除权、生效、登记、支付、供应商首次看到的时间；拆股调整股份数量，不制造利润；现金股息先产生应收、支付时入现金；换股/并购/分拆按证据处理。
- 若价格已经做总回报调整，不得再次把股息作为利润加一次；回测现金与证券头寸必须严格平衡。
- **通过**：真实拆股、分红、收购、停牌、退市案例的事件驱动账本与交易方程核对；无法结算的策略运行中断并展示原因。

### B06 PIT 发布时点/回溯版本
- 原始 SEC 文件以 accession + 接收时间建立可用性，严禁把财务季度截止日当披露日。
- 对供应商后期修订、当前汇总快照与历史原稿分别标记；无发布时间的历史价格/元数据仅用于允许的研究层级。
- **通过**：财报发布前一天无法使用该财报指标；修订不静默改变过去因子信号。

### B07 行业分类
- 先构建 SIC as-filed 的历史分类，保留来源及日期；SIC → 自定义行业组映射须显式版本化、承认非 GICS；映射不到显示 UNKNOWN，不强行分组计算残差。
- 行业残差 Alpha 缺行业信息时因子标 `N/A`，行业风控需要未知资产风险上限或 BLOCK。
- **通过**：至少一只真实行业历史变更证券的时间切换无穿越。

### B08 PIT 质量/规模
- 质量因子通过 SEC as-filed 逐期事实+计算公式版本得到 ROA/ROE/现金流；规模按 `price_raw × 已知流通或总股数` 构建，清楚区分总市值和自由流通市值。
- 财报 ARQ/ART 与 MRQ/MRT 不混合；股本发布日期/拆股变化/多股类口径须显式标注。数据不足时禁用质量、规模，不影响已完整的价格因子。
- **通过**：季度差、TTM、单位、股数口径、修订时间各有真实公开案例回归。

### B09 数据驱动接线（最高工程优先级）
- 删除 `if source != fixture: reject` 这类供应商名硬编码；用 `DatasetBundle + CapabilityRegistry` 检查真实数据证据。
- 接口：`load_real_bundle(as_of, universe, capabilities)` 返回行情/身份/行动/分类/财务/版本证据集合；没有能力直接结构化报错，而非默默进入任何假数据通道。
- 对 `factor -> model -> backtest -> paper -> report -> UI` 做一次完整真实数据贯通测试。
- **通过**：真实来源完成相应级别研究/回测，而不合格时精确指出缺哪张表/哪个时点。

### B10 调度时钟/延迟
- 使用交易日历 + 实际 `first_observed_at` + `decision_at`，不是固定 `close+15` 的伪时钟；对 EOD 供应商延迟动态选择有效冻结截止，最晚必须赶在次日预定入场时间之前。
- 缺关键源、延迟、早收盘、节假日、DST、断网时不补历史决策；记录 `MISSED_CUTOFF` 并停该轮模拟。
- **通过**：时钟回归案例真实交易日 + 单元函数测试；从未出现 `data_observed_at > decision_at`。

### B11 成交与成本的实证基础
- 确定信号在 t 收盘后冻结，只允许 t+1 及以后的交易；开收盘均须基于真实 raw bar，不允许当日收盘用已知当日收盘信号成交。
- 成本默认按明确的**情景假设**展示，直到实测 NBBO/成交数据可验证；设置保守滑点与冲击上限。不能把 bps 情景写成实测成本。
- 止损跳空按开盘不利价格处理；同日止损/止盈顺序不明时用保守路径或中止；停牌/缺 bar 不能成交。
- **通过**：每笔交易可还原当时信号、可交易价格、成本及现金/股份双重记账。

### B12 模型预测与概率校准
- 使用简单基线（常数上涨概率、市场持有、单因子）对照逻辑回归/GBDT；仅在历史过去数据上拟合校准。
- 训练—验证时间窗 purge horizon、embargo；避免重叠标签当独立观测，报告块 bootstrap/按日期聚类不确定性。
- **通过**：报告真实 OOS Brier/RankIC/交易成本后收益；若无优势如实显示“不优于基线”，不得调参到赚钱再改历史结论。

### B13 最终独立样本
- 建立实验登记 `research_registry`（公式、参数、数据、成本、指标）；历史最终测试数据封存，只有冻结参数和 hash 后才能解封一次。
- 如果此前已窥视测试集，重新指定尚未用于决策的更晚前向数据；不要凭技术重命名让旧样本重新“独立”。
- **通过**：有冻结与解封审计记录；可以完全复现，允许负面结果。

### B14 真实前向影子交易与券商模拟
- 模式一 `FORWARD_SHADOW`：冻结真实可用信号，使用下一时段真实 raw 价格、清楚标注模型估计成交，不显示虚构“实际成交”。
- 模式二（可选）`BROKER_PAPER`：如果用户自行开通券商模拟盘，使用券商返回的真实 paper fill event（本质为券商模拟成交）与行情 provenance 对账，不与实盘成交混称。
- 从启用之日真实逐日累积；无权“补足过去 30 天的前向记录”。
- **通过**：不重复下单、断电恢复、跨交易日结转、分红及退市阻断、重复运行幂等；连续真实运行期内再验收日常稳定性。

### B15 运行与运维
- 真实数据下载单写队列 + 数据库事务/文件锁；备份、hash、版本、错误通知；Windows 和 Linux 分别实际运行测试，而不只声明兼容。
- UI 至少有：数据证据页、缺失原因、供应商连接状态、历史可用区间、最近有效交易日、策略运行记录、每份报告真实数据来源。
- **通过**：真实离线重放、备份恢复、故障注入、跨平台 CI 有真实执行日志；已完成与待验证分别标记。

## 4. 能力矩阵：禁止用一种“回测通过”掩盖数据缺口

| 功能能力 | 必需真实证据 | 不满足时 |
|---|---|---|
| 市场分析 | SPY/ETF 有效 EOD + 真实市场交易日历 | 不出当日结论 |
| 经典风格监测 | 真正的因子收益或明示为 ETF 相对收益代理 | 不展示伪风格数据 |
| 个股价格因子 | 原始/可核验复权日线 + 历史有效证券 ID | 拒绝缺失样本 |
| 行业残差因子 | 历史行业类别 + 同期行业收益 | 因子不可用 |
| 质量/规模因子 | 历史 PIT 财报/股数及身份映射 | 因子不可用 |
| 探索性回测 | 真实历史价格 + 明示样本范围和成本假设 | 标为不可用 |
| 广义历史回测 | 退市、代码映射、公司行为、PIT 名册、交易价 | 显示 BLOCKED |
| 前向影子决策 | 在决策前已实际取得的真实数据 + 冻结快照 | 本轮跳过 |
| 券商模拟成交 | 有纸面券商事件及对账记录 | 不出现“已成交” |

`grade` 不以 UI 手动编辑；由数据证据自动派生。没有完整历史证据时，不要把“局部合格”显示为“全市场合格”。

## 5. 回测交易语义（项目默认规范）

1. 目标市场为美国上市普通股/ETF；首版只做多，不做期权、杠杆和真实订单；交易期 1/3/5 日。股票池必须明确交易所、类别、排除 ADR/优先股/OTC 的规则或允许规则；不可以用当代筛选结果回填。
2. `asof_t` 为美股某交易日经核验的数据冻结时间，次一交易日开盘才可下单；不存在“知道收盘后信号而以刚收盘价成交”的设定。
3. 信号历史样本可使用真实、当时可知的信息；后期修正的数据只能用于事后数据准确性研究，不能冒充信号实时可用。
4. 价格信号可以用复权一致的历史收益，但撮合/持仓使用同一币种的 raw/事件账本。缺失或无法核实的价格不能插值成可成交价格。
5. 持仓日数严格定义：第一个可成交日开盘算第 1 日，H=3 于第 3 日收盘退出；止损优先、公司行为、停牌等例外明确写明。
6. 限额按账户风险预算、ADV 参与率、最大持仓/行业/总敞口；交易成本标出费率来源、时点、单位及是实测/估算。
7. 允许无策略优势、无成交、无信号；严禁默认填一条漂亮收益曲线。

## 6. 数据验收指标（实际值必须由 Codex 运行生成）

- `coverage`: 股票×交易日实际条数/预期条数；预期基于股票**自身挂牌与退市生命周期**，不能对未上市期间判定缺失。
- `uniqueness`: `(security_id, session_date, feed, adjustment)` 不重；若有修订记录用版本主键。
- `validity`: 价格 >0、非负成交量、H >= max(O,C)、L <= min(O,C)；对停牌/特殊行情保留合法例外及来源。
- `timeliness`: `source_published <= available_at <= decision_at` 对需要 PIT 的特征成立；只有已可核验发布时间的记录才能使用这个不等式，不可创造发布时间。
- `actions`: 对每一个拆股/分红事件，日期、股份/现金调节与 provider 记录相符。
- `lineage`: 每个因子值到具体真实数据源、下载运行 ID、计算版本均可追溯。
- `reproducibility`: 相同 snapshot hash、代码 commit、参数 → 完全相同输出。数据回填或算法变化生成新版本。
- `security`: API key 使用 `.env` 或密钥管理器，不写入仓库或日志；只做只读行情和模拟操作。
- 不设置拍脑袋的统一 99.9% 数据通过率：每种数据源、股票类型和年份先实际测量，再冻结具名阈值，且核心合规性（未来泄漏、成交造假）为零容忍。

## 7. 用户界面与使用体验修复

- 首屏移除全部预置演示指标与模拟收益，空仓/未完成数据表现为真实空状态。每张图显示 `来源、口径、最近更新时间、覆盖范围、计算版本`。
- 左侧提供：数据中心、市场状态、经典因子、个股因子研究、回测中心、每日信号、前向模拟、审计与设置。
- 数据中心：真实来源连接状态、可用股票/日期数、缺失条目、待同步任务、历史退市覆盖、证据下载。
- 研究页：若不可用，展示缺失能力及修复入口，不能用合成数字代替。
- 回测页：明显区分“探索回测”“历史严格验证”“真实前向影子”，收益图注明“真实行情+模拟成交假设”；只有原始真实交易事件才显示“真实执行成交”（本项目首版禁止）。

### G0：仓库审计与真实数据禁用门槛（预计 6–10 人时）

- **验收**：前后端真实空数据状态可用；grep + integration tests 证明无法从生产路径产生合成市场结果。

### G1：数据权限及真实行情贯通（预计 10–18 人时）
- 针对账户运行 Alpaca live read-only 授权/历史 SIP 探测（不能代用户注册/付款）；实现 fetch/paging/raw/parquet/sha/对账；真实 ETF 与个股测试。
- **验收**：报告真实覆盖数、起止日期、缺页、原始响应证据；本地调用 API 成功并可离线重放。

### G2：证券身份、股票池、公司行为（预计 18–35 人时；订阅可用后）
- 将 Sharadar/Norgate/可用许可源做完整实测并整合 `security_master/actions/universe`；修复退市和 raw vs adjusted；交易账本按公司行为结算。
- **验收**：历史换代码、拆股、分红、IPO、退市至少各一个实际可审计案例；严谨历史回测能力仅在每一项满足后解锁。

### G3：PIT 财务、行业、风格因子（预计 12–25 人时）
- SEC 原稿、SIC 历史分类、可选 Sharadar ARQ/ART；建立符合披露时点的质量/规模/行业残差；因子收益更新时间核查。
- **验收**：真实公告日边界、历史调档、时点和行业变更测试通过。

### G4：模型回测/日报/模拟系统全链路接线（预计 16–30 人时）
- 用能力矩阵替代 fixture 限制；从真实 bundle 贯通 4 模型、回测、报告、UI、前向影子；日历和时间冻结；三档成本情景（明确假设）。
- **验收**：真实数据进入指定功能、不合格失败关闭；没有数据的页面空状态；严格禁止用虚构成交交易。

### G5：可信度/自动化/日常验收（预计 12–25 人时）
- 时间序列 OOS、封存最终测试、告警、每日调度、系统启动恢复、Windows/Linux 测试、备份、真实数据重放与报表导出。
- **验收**：所有测试真实执行证据及失败清单；真实前向观察必须经过实际交易日才能积累，不能即时补造。

**参考总工程量**：约 74–143 人工小时（不含外部数据许可等待和真实交易日观察）；Codex 编码可降低手工工作量，但**不能缩短必须发生的市场观察时间**，也无法保证模型获得 Alpha。按用户每周验收 10–15 小时，若完整数据授权、网络及源代码可及时提供，工程迭代约 6–12 周；若要连续 20 个真实交易日验证前向稳定性，还需按自然交易日实际累计。
