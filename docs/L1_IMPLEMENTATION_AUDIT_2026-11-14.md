The `feature_coverage.csv` generated by a research run reports observed
feature rows, rather than claiming provider permission or a point-in-time
historical vintage. For calculated features the cutoff is not substituted for
an unknown source availability time. All entries remain ineligible until the
required independent provenance and PIT checks are completed.

A separate single-session audit of the verified 2026-11-13 close snapshot is at
`outputs/l1_snapshot_audits/2026-11-13-provenance/feature_coverage.csv`. It finds 2 of
57 features with values from that one session; rolling windows deliberately
remain unavailable. These numbers are not estimates of full historical feed
coverage. Run it with `python -m quant_research.workflow.l1_snapshot_audit
--asof 2026-11-13 --output <new-output-directory>`.

The current-vintage fallback verifies the source bundle and shows only SPY
same-session open-to-close return and close location; it does not use raw
multi-day prices as corporate-action-adjusted history. The new daily stage
records the one-session audit but does not train, freeze or settle a model.

The E01 comparison now uses a recursive daily-return EWMA on the purged
training window and reports its MSE; its deliberate embargo lag must be
considered when interpreting comparisons. The research runner defaults to
evaluating every eligible session. Neither change establishes model advantage.
E03 reporting includes mean squared error, quantile hit rates, and explicitly
uncalibrated Brier scores versus historical-frequency baselines; E02 reports
multiclass log loss. `oos_metrics_by_year.csv` splits those results by year.
These are implemented metrics, not results from a qualified real-data run.
The L1 research CLI's `--ablation` option records base-only and extended
feature predictions, pairs the same session and label, and reports paired
loss differences. This is one predeclared feature-set comparison, not a
complete multiple-testing correction or proof of predictive improvement.
First-touch labels also record the trading-session offset; the mean offset for
correctly classified UP/DOWN events is descriptive and does not prove an
operational or intraday lead time.
The historical research entry point requires consecutive XNYS sessions,
timezone-aware source and cutoff timestamps, and a decision cutoff after the
session close and before the following open. This rejects invalid input; it
does not itself authenticate a vendor's claimed historical publication time.

On the current Windows workstation, `QDR-L1-Daily-Observation` is registered
for 06:30 China time on Tuesday through Saturday, using `scripts/run_daily.ps1`.
The task requires an interactive user session and its first scheduled run has
not yet occurred. The script itself checks the XNYS close-to-next-open window;

## Candidate sources requiring separate qualification

- [FRED / ALFRED real-time periods](https://fred.stlouisfed.org/docs/api/fred/realtime_period.html)
  support date-based historical vintages. The [API terms](https://fred.stlouisfed.org/docs/api/terms_of_use.html)
  require a registered API key; this project must not register an account or
  solicit a key automatically. Date-level vintages alone do not establish an
  intraday release timestamp, underlying series license, coverage, or entitlement.
- Alpaca documents [corporate-action data](https://docs.alpaca.markets/us/reference/corporateactions-1)
  and [historical option data](https://docs.alpaca.markets/us/docs/historical-option-data).
  Existing local SIP ETF access does not establish the account's option-data
  entitlement, full history, all-event coverage, dealer positions, or cost.
  Each separately supplied dataset requires its own receipt and permission review.
