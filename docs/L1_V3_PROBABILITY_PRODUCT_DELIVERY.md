## 使用路径和主要接口

- 页面：`/studio#market`（原有深色设计）。点 H1/H3/H5 切换同一次返回的预测明细，不重复拉主模型。
- `GET /api/v1/l1/v3/overview`：只读 on-demand V3 研究模型；默认不写归档。
- `GET /api/v1/l1/v3/overview?archive=1`：显式冻结研究快照；前端默认采用。反复访问相同内容只产生一份文件，不覆盖原有档案。
- `GET /api/v1/l1/v3/overview?archive=1&refresh=1`：强制从供应商更新然后重新研究（不同真实数据版本可产生新的快照）。
- `GET /api/v1/l1/v3/history`：已有轻量冻结快照索引。
- `GET /api/v1/l1/v3/outcomes`：到期后的真实情景与三分类 Brier。
- 原始数据：`/api/v1/l1/v2/overview?horizon=3`、`/api/v1/l1/v2/official`、`/api/v1/l1/v2/extended`。

真实行情缺失/权限不足则返回 409 与明确错误代码；前端对应区块展示未准备好，不用演示比例占位。

## 一笔预测是如何算出来的（数字全部来自运行结果）

1. 使用 SPY/RSP/IWM/HYG/LQD 的真实交易所日线，并按已完成交易日截断。只使用固定 7 项 ETF 特征计算当前预测：SPY 五日收益、RSP−SPY、小盘−SPY、波动比、HYG−LQD、20 日下行波动、20 日回撤。已接入的非 PIT 期权和宏观现值**不偷加进模型**。
2. 在训练时间段拟合 `StandardScaler`，实际输出各项原值、标准化值、UP 类别的真实 Logistic 系数贡献与截距。这是 logit 贡献而不是“概率增加 N 个百分点”。
3. 生成 H1/H3/H5 的互斥三类研究概率。场景边界固定为预测日可观察的 `0.6 × RV20 × √H`，并限制在 0.3%–3.5% 之间。收益从 T+1 开盘计算至 T+H 收盘；价格刚好等于阈值归入震荡。
4. 在训练结束之后、测试之前的独立校准窗口选择温度系数，计算每一类原始/校准概率及 pp 差异。模型拟合不读取校准/验证标签。
5. 每约 52 个交易日向前滚动一次冻结训练/校准，验证末尾约 260 个已完成研究样本，并与训练窗口历史频率基准比较多分类 Brier、LogLoss、ECE。阈值：至少 200 个 OOS 点、4 个滚动块、LogLoss 低于基准 1%、Brier 优于基准、ECE ≤ 0.10、至少 3 个块 Brier 优于基准。**这些只是数值门槛，不替代外部 PIT 审核。**
6. 概率引擎始终输出 `historical_pit_verified=false` 和 `admitted_probabilities=null`；数值可作为「研究估计」显示，但不可声称已校准认证或保证胜率。

V3 默认按需请求近 2500 自然日内的 5 只核心 ETF 日线，要求至少 900 个交易日可计算观测。可能受 Alpaca 权限、数据覆盖和单响应 5MB 限制而返回不足/阻塞；这是数据质量失败，不应改用合成行情。

## 归档与评估

- `outputs/l1_v3_research/YYYY-MM-DD/<sha-prefix>.json`：只存小型研究输出、真实证据摘要与模型明细；没有保存全部日线行情。快照不可覆盖。
- `outputs/l1_v3_outcomes/YYYY-MM-DD/<sha-prefix>_H{1,3,5}.json`：在 T+H 当日收盘+延迟后，根据届时真实 SPY 日线补写实际收益、实际情景及三分类 Brier。原预测文件保持不动。
- 归档与到期核验在页面请求 `?archive=1` 时触发，并非后台定时任务；若长期不访问系统，则不会自动执行。
- 命令行手动归档：`python -m quant_research.workflow.l1_v3 --root . --save-snapshot`。
- 现有 32MB/32 条供应商原始请求轻量缓存保留；V3 在同一服务进程中最多缓存 3 个研究结果、每个 10 分钟，避免反复重训，不存储模型训练仓库。

## UI 信息层级与交互

原深色变量：`--bg:#0a1020`、`--panel:#131e30`、`--teal:#4bd7bd`。

1. **市场状态条**：简短结构结论、SPY 收盘、五日走势、RSP−SPY、卖压评分。不再保留巨型文案卡片。

3. **选中期限的计算记录**：7 行指标原值→标准化→UP Logit；紧接原始三类概率→温度校准后的三类概率及 pp 差值；Brier/基准/样本/OOS/资格。
4. **向下浏览数据监测**：价格与趋势、市场广度、波动与期权、信用与利率、资金与持仓、宏观事件；显示真实历史时才画迷你图，不能凭当前单点生成趋势。
5. **前向归档核验**：只展示真实到期评价记录；旧版完整研究通过按钮按需切换，E01/E02/E03 原路由保留。

不将“第一屏/第二屏”、“设计草稿”等文字写入产品界面；滚动与导航就是正常单页内容。

重点检查：

- H1/H3/H5 标签严格使用 T+1 开盘到 T+H 收盘；任何 T+H 尚未完成的标签不能进入训练。
- 校准参数仅在独立校准窗口拟合；滚动验证不读取之后的标签。
- V3 API 缺数据时 UI 不出现 62% 等模拟值；V2/官方指标继续可独立展示。
- 归档重复请求内容哈希相同；后验结果需等待对应交易日结束，篡改原快照被拒。
- 375px 与桌面宽度适配，深色视觉和 L2/L3/L4 不变化；原 V2 研究入口仍可打开。

## 无法凭本轮代码宣称的事项

本轮新模型已经具备研究估计计算、时间序列校准与验证的代码闭环，但**没有取得用户真实 Alpaca 环境的联网验收**，也没有历史 PIT 供应商证明，因此不能声称已正式获得准确的 62% 上涨胜率或已通过实盘资格。Cboe/CFTC/OFR 等当前公开源的发布时点审计和因子增量验证需要来源提供真实历史观测记录；未通过时不参加 V3 训练。

非线性 HGB 是待评估的增强模型，不能在未完成同一套 PIT/OOS 对照前与 Logistic 任意混合、给出人为 35%/25% 等“模型贡献比例”。此次选择了结构清晰、可复算的 Logistic 概率基础模型作为唯一 V3 研究输出。
