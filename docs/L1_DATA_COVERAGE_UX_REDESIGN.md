# L1 数据覆盖与信息架构整改 · 2026-11-15

## 本轮已落地的 UI 整改

原 12 张并列大卡错误地将底层数据观测作为 12 个可比的市场结论；同时不同量纲显示成裸数值（如 0.03、19.30、2.40），缺数据的维度显示「0/0 项特征」，误导阅读。

新的页面阅读顺序：
1. 当前市场结构研判：三项评分与解释，显著声明**非概率**，且只使用现有价格、波动、RSP/IWM 与信用 ETF 代理特征，不冒充已经实现完整 12 维综合预测。
2. H1/H3/H5 历史相似条件研究：保留样本量、历史分布、路径频率与是否通过验证的区分；不把回顾性概率标为前向胜率。
3. 数据证据与缺口：默认只展示 12 维覆盖概览及待补数据清单，展开后按市场内部、波动衍生品、交易资金、跨市场事件四组核查；每个指标保留来源、数值、单位与缺失原因。
4. 原 E01/E02/E03、验证工具折叠在高级研究区，延迟请求。L2/L3/L4 不修改。

所有 12 维必须保留。缺失数据不计零、不隐式插值、不把代理指标称为官方真实股票广度。

## 为什么当前仍有数据缺口

V2 当前实际适配数据：
- Alpaca：19 只 ETF 的日线与可选报价快照。SPY/RSP/IWM/HYG/LQD/行业 ETF 等提供的是**部分市场结构代理**。
- Cboe：VIX 历史收盘，无法代替完整期权偏斜、持仓和波动期限结构。
- FRED：可选利率、SOFR 和高收益信用利差，**未配置本地 FRED_API_KEY 时不可用**。

尚无独立适配器或完整来源：全市场个股 PIT 广度、完整期权持仓与交易商净头寸、Level-2 订单簿及真实订单流、ETF 申赎/真实持仓拥挤、正式宏观事件意外值与历史可用时间等。本次 UI 改造不改变这些数据源事实。

## 后续数据接入优先顺序

| 优先级 | 接入事项 | 要求/注意事项 |
| --- | --- | --- |
| P0 | 本地 FRED 权限健康检查 | 配置 FRED_API_KEY 后验证 DGS10、SOFR、BAMLH0A0HYM2 的近期可用日、来源和延迟 |
| P1 | 真实股票广度 | 可信股票池、涨跌家数和创新高低，声明供应商覆盖；历史 PIT 无法由当前股票列表倒填 |
| P1 | 可授权期权数据 | OI、期限、put/call、IV/Skew 等；OI 不等于交易商净 Gamma |
| P1 | 宏观事件时间 | 正式事件日历、发布时间、已发布与预期值的时点准确性 |
| P2 | 真实 ETF 申赎与 COT | 使用基金发行人/CFTC/合规供应商数据，不能把价格涨幅当净资金流 |
| P2 | 深度流动性 | 供应商许可与限频允许时接入 Level-2 或成交方向数据；SPY 一档不代替全市场盘口 |

不要求本地持久保存全市场行情；数据按需获取并限量缓存，但保存预测冻结记录、来源签名和最小可复核的审计证据。

## 验收

- 首屏能在无需展开 12 维的情况下回答：当前风险、未来期限研究、主要驱动。
- 12 维按 4 组展示，数字类型带明确单位；不能出现 0/0 项特征。
- 缺失项能直接看到待接入名单，详细展开后能看到具体缺口。
- 加载中不标成 MISSING；API 失败不生成价格或概率。
- 原研究接口默认不启动，展开时再加载；七个工作区之间的导航不受影响。
- Node 单元渲染验收：tests/test_l1_information_architecture.py。实际供应商覆盖仍需本地验收。
