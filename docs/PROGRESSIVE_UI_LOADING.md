# QDR Studio 全工作区渐进式加载（2026-11-14）

## 已实现

- 六个工作区和数据中心的页面外壳优先渲染：路由切换不等待所有数据接口完成。
- 当前工作区的数据 GET 请求并行启动，首次渲染使用明确的加载态；单个请求成功后调度局部进度刷新，其他模块继续加载。
- 请求以 URL 为键去重并内存缓存，成功 TTL 60 秒、失败 TTL 12 秒，最多保留 80 条（不建立持久行情库）。视图 GET 超过 30 秒显示超时失败，不阻挡页面。
- 后台状态栏请求不阻塞正文；人工点击右上角刷新会清除视图缓存并重新检查。
- L1 V2 自动扫描使用一份多期限结果，H1/H3/H5 切换不重复请求同一份扫描；默认收起的历史研究区**不发起**旧模型、样本外验证、异常归档等额外请求，展开后再按需加载。
- 已实现滚动位置、展开状态、文本输入焦点保留；渲染失败、数据缺失与加载中在文案上明确区分。旧研究资格/真实性校验保持不变。
- 严格只优化浏览器加载与内存请求缓存；没有改变 L1 评分算法或数据资格，加载快不等于新的模型研究证据。

## 验收

1. 从无缓存浏览器首次进入 /studio#market，立即出现标题/骨架，再出现 L1 研判结果，不能停留在全页“正在读取真实研究数据”。
2. 浏览器 Network：历史研究折叠时不得请求 /api/v1/l1/anomalies、/api/v1/l1/validation、/api/v1/market/research；展开后才产生这些 GET。
3. 在 Network 人工延迟某个 GET 后，其他已完成模块应先展示；慢接口不得使全部卡片空白。
4. H1/H3/H5 切换不会重复触发新的 V2 scan URL（不含人工刷新）；右上角全局刷新会重新发起请求。
5. 切到 /studio#style、#lab、#screen、#risk、#data，页面骨架先出现；数据接口失败保留各自错误状态，不显示合成市场值。
6. 手机端无横向溢出，键盘操作与展开的研究区不会因数据回调被自动关闭。
7. 运行 pytest tests/test_progressive_loading.py；动态测试需要本地 Node.js。

## 实施边界

这是渐进式加载而不是新增服务端并行任务队列。页面内共享状态的旧组件仍可能整体重绘，但各 GET 结果已经独立完成与渐进展示。后续如需更精细的“只替换某张卡片而不重绘工作区”，可按页拆为独立视图组件；不应为了此目的改变预测计算或供应商数据权限。
